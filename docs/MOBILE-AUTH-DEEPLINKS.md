# Mobile auth and deep links

## Supported auth path

1. User signs in on **web** (email/password or OTP). Better Auth issues a **session** row and, with the **bearer** plugin, returns a **session token** in the `set-auth-token` response header on successful sign-in/session responses.
2. The mobile app stores that token in **Expo SecureStore** (key `jurisly_session_token` — see `apps/mobile/lib/auth-token.ts`).
3. **`TrpcProvider`** sends `Authorization: Bearer <token>` on every tRPC request to `EXPO_PUBLIC_API_URL`.

This avoids depending on httpOnly cookies in React Native, which do not apply to the native HTTP stack the same way as a browser.

## Deep links and universal links

### Universal Links (Preferred for Production)

Jurisly uses **universal links** for seamless deep linking. Universal links use standard HTTPS URLs that:

- Open the mobile app automatically when installed
- Fall back to the web version when the app is not installed
- Work without user interaction or app switching prompts

**Configuration (apps/mobile/app.json):**

```json
{
  "expo": {
    "ios": {
      "associatedDomains": ["applinks:app.tryjurisly.com", "applinks:tryjurisly.com"]
    },
    "android": {
      "intentFilters": [
        {
          "action": "VIEW",
          "autoVerify": true,
          "data": [
            {
              "scheme": "https",
              "host": "tryjurisly.com",
              "pathPrefix": "/"
            },
            {
              "scheme": "https",
              "host": "app.tryjurisly.com",
              "pathPrefix": "/"
            }
          ],
          "category": ["BROWSABLE", "DEFAULT"]
        }
      ]
    }
  }
}
```

**Production Requirements:**

1. **iOS**: Publish an Apple App Site Association (AASA) file at `https://tryjurisly.com/.well-known/apple-app-site-association`
2. **Android**: Publish a Digital Asset Links JSON file at `https://tryjurisly.com/.well-known/assetlinks.json`
3. Verify domain ownership for both platforms
4. Deploy with proper SSL certificates

### Custom Scheme (Fallback)

The app is also registered with the custom scheme `jurisly://` as a fallback for:

- Local development and testing
- Links from non-web contexts where universal links may not trigger
- Explicit app-only links (e.g., from native integrations)

**Format:** `jurisly://[screen]?[params]`

**Examples:**

- `jurisly://lawyers?city=Delhi`
- `jurisly://notice-scanner`
- `jurisly://kya-karein`

### Locale-Aware Deep Linking

All deep links support locale-prefixed paths to maintain language context:

**Universal Link Examples:**

- `https://tryjurisly.com/en/notice-scanner` → Opens Notice Scanner in English
- `https://tryjurisly.com/hi/lawyers?city=Mumbai` → Opens Lawyers in Hindi, filtered by Mumbai
- `https://tryjurisly.com/en/kya-karein` → Opens Emergency Guide in English

**How it works:**

1. Expo Router automatically handles file-based routing under `apps/mobile/app/(tabs)/`
2. The app's i18n provider detects the locale from the URL or uses stored preference
3. Navigation preserves locale context across screens
4. Links generated by the API (e.g., WhatsApp bot) include locale prefix

**Implementation in WhatsApp Bot:**

```typescript
function link(opts: { base: string; locale: string; path: string }): string {
  const base = opts.base.replace(/\/$/, '');
  const path = opts.path.startsWith('/') ? opts.path : `/${opts.path}`;
  return `${base}/${encodeURIComponent(opts.locale)}${path}`;
}
```

### Deep Link Testing

**Test universal links:**

1. Deploy to a device (not simulator/emulator) with the app installed
2. Send yourself a link via Messages, WhatsApp, or Email: `https://tryjurisly.com/en/notice-scanner`
3. Tap the link → app should open directly to Notice Scanner
4. Uninstall the app and tap the link → should open web version

**Test custom scheme:**

1. Use ADB (Android) or xcrun (iOS) to trigger: `adb shell am start -a android.intent.action.VIEW -d "jurisly://lawyers"`
2. Or create a test HTML page with a link: `<a href="jurisly://notice-scanner">Open App</a>`

**Test locale preservation:**

1. Open app and switch to Hindi
2. Share a feature link from within the app
3. Open the link → verify the app stays in Hindi
4. Open a link with explicit `/en/` prefix → verify it switches to English

## Environment

- `EXPO_PUBLIC_API_URL` — Nest API base URL (no trailing slash).
- `BETTER_AUTH_URL` or `NEXT_PUBLIC_APP_URL` — Web base URL used by WhatsApp bot and deep link generation.

## Production Checklist

Before enabling universal links in production:

- [ ] Publish AASA file for iOS at `/.well-known/apple-app-site-association`
- [ ] Publish Digital Asset Links JSON for Android at `/.well-known/assetlinks.json`
- [ ] Verify domain ownership in Apple Developer Console and Google Play Console
- [ ] Test on physical devices (universal links do not work in simulators)
- [ ] Ensure SSL certificates are valid and properly configured
- [ ] Update `BETTER_AUTH_URL` to production domain in API environment
- [ ] Test deep links from WhatsApp, email, SMS, and web browsers
